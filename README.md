# 列宾 · Liebin

> 画《伏尔加河上的纤夫》之前，列宾在伏尔加河边住了两个夏天，画了大量习作，才动定稿的笔。

落地页：[liebin.caojuege.com](https://liebin.caojuege.com)

一个 Claude Code / Claude Skill：**在动手写页面之前，先把设计方向做成三张能被否决的样张。**

---

## 它解决的问题

用 AI 做设计最常见的失败不是「做得丑」，而是：

> **「做出来的和我想要的不是一个东西，但我说不清哪里不对。」**

等页面写完再返工，成本已经付掉了。

列宾只做一件事：**把设计方向提前具象化到一个能被否决的形态**——三个用你的真实文案渲染的方案，并列在一张 HTML 上，让你指着说「要这个、不要那个、那个的圆角太软了」。

你骂出来的那句原话，才是真正的设计约束。

---

## 怎么用

装好之后，直接说人话就行：

```
照着这个网站做一个 → https://example.com
帮我这个落地页定个设计风格
我想要那种高级感（什么参考都没有也可以）
```

Claude 会自动走完五步：

| 步骤 | 做什么 |
|---|---|
| **1 · 收料** | 参考是什么？要设计的是什么？**必须拿到真实文案**，占位文字做出来的样张一定是骗人的 |
| **2 · 定轴出样张** | 三个变体沿**一条明确的轴**排开，每个渲染**三屏**：首屏 / 核心操作屏 / **空状态** |
| **3 · 确认对话** | 选哪个？另外两个哪里不要？你的用户在什么状态下打开这个产品？ |
| **4 · 回写 DESIGN.md** | 用 Google Labs 的 DESIGN.md 规范，把你的原话逐字写进 Don'ts，**每个数值标出处** |
| **5 · 验收** | 页面落地之后回来看一眼：样张和成品并排，只问「这跟你当初选的还是同一个东西吗」 |

产出一份 DESIGN.md，交给 Claude Code / Codex 去写代码。**列宾不替你开发产品**——第五步也不写代码，只回答「像不像」。

---

## 三个刻意的设计

**轴不是随机的。** 三个「随机好看」的方案，你选完什么也没学到。轴由「你缺哪类信息」决定：

| 手上有 | 缺的是 | 三变体沿这条轴分 |
|---|---|---|
| 一张截图 | 精确数值 | 紧凑 / 基准 / 舒展 |
| 网址或 DOM | 意图与取舍 | 忠实复刻 / 取其气质 / 反向克制 |
| 一份 design md | 落到你内容上的合身度 | 信息密度 高 / 中 / 低 |
| 只有一句话 | 全部 | 三种不同的气质解读 |

**第三个变体故意偏离参考。** 你贴那张图的时候，往往并不真的想要那张图，只是没有别的语言描述自己想要什么。第三个变体的作用，是把这件事逼出来。

**空状态屏一定要渲染。** 那是最能暴露一套风格撑不撑得住的地方，也是所有 AI 生成的样张都会跳过的地方。绝大多数「看着挺好后来崩了」，都崩在第二三屏。

## 能偷什么，不能偷什么

名字叫「偷设计」，线得划清楚。

**可以拿「怎么做」**：版式骨架、留白比例、字号层级关系、色彩之间的对比关系、节奏和密度。这些是设计判断，本来就靠互相看长进。

**不能拿「那一份东西」**：logo、没授权的字体文件、图片和插画素材、成段文案、有版权的图标集。

灰的地方问一句：**换掉我的内容之后，还有人会把这两个页面认错吗？** 会，就是搬了；不会，就是学了。

代码同理——先看 license，没写 license 的默认按不可用处理。

---

## 四个坑，列宾帮你避开

- **数值崇拜** — 参考里的 `-2.46px` 字距是 80px 拉丁标题下的 `-0.031em`。照抄到 48px 中文标题上会挤成一团。所有间距一律转 em 再迁移，**中文标题不用负字距**。
- **占位文字** — Lorem ipsum 会让所有方案看起来都还行。中文文案的长度、语气、断行会彻底改变一个设计成不成立。
- **只给一个方案** — 单方案只能换来「嗯挺好的」或「感觉不太对」，两种回答都零信息量。
- **替用户写 Don'ts** — 模型生成的负面约束永远是「保持一致性」「避免视觉噪音」这种正确的废话。**Don'ts 这一段只能由人填。**

## 安装

```bash
git clone https://github.com/ShaohuaDavidLee/Liebin.git ~/.claude/skills/liebin
```

重开一个 Claude Code 会话即可生效，或直接 `/liebin` 调用。

放进项目里只给这个仓库用也行：克隆到 `.claude/skills/liebin`。

## 仓库结构

```
SKILL.md                        主流程：五步走完，什么时候该停，能偷什么不能偷什么
references/
  intake.md                     四条收料入口，各自能拿到什么、必然缺什么
  variants.md                   三变体怎么分轴、怎么渲染、拿到反馈之后怎么定位
  design-md.md                  DESIGN.md 八小节规范 + 来源标注 + CJK 扩展 + lint 的四个坑
  verify.md                     验收：唯一必须回答的一问、六项体检、工具的盲区
scripts/
  proof.mjs                     样张脚手架，无依赖。拦占位文字，拦不满三屏
  verify-page.mjs               验收体检，要 playwright。装不上有保底路径
assets/
  preview-template.html         不用脚本时的手搭模板
evals/
  evals.json                    触发准确性与流程完整性测试
site/                           落地页静态站（Cloudflare Pages 产出目录）
wrangler.toml                   Pages 配置
```

两个脚本都是可选的。`proof.mjs` 只替你搭外壳，三个变体的内容还是得自己写；`verify-page.mjs` 装不上就退回肉眼——
把落地页截图和样张并排贴回对话里，那条路任何环境都走得通。

样张是**单文件 HTML**，内联 CSS/JS，除 Google Fonts 外无外部依赖，双击就能打开。它的寿命是二十分钟——别用框架，别上构建工具。

落地页是另一回事：`site/` 是给 Cloudflare **Pages** 用的静态站（不是 Worker）。没有构建命令，产出目录就是 `site`。自定义域名 `liebin.caojuege.com` 在 Pages 项目里绑一次即可。

## 它不做什么

**不负责提取设计系统。** 提取器满大街都是（design-extractor、Claude Design 的 web capture、Chrome DevTools MCP），提得再准也解决不了开头那个问题。列宾里的提取只是给三个变体找个起点，粗糙没关系——它马上就要被你否决和修正。

**不继续开发产品。** DESIGN.md 交付即完工。
