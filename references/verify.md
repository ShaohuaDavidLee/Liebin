# 验收：这跟你当初选的，还是同一个东西吗

列宾到 DESIGN.md 就停——这一条不变。但「停」不等于「不回头看」。

DESIGN.md 交出去之后，页面是别的 agent 写的。**没有任何机制检查它写出来的东西跟你当初指着说「要这个」的那一版还是不是一回事。**
样张在第二步就有了，落地页在第五步就有了，把这两张图并排看一眼的成本接近零——不看才是浪费。

---

## 一、只有一问是必须回答的

> **这跟你当初选的那一版，还是同一个东西吗？**

**不追求像素一致。** 样张是 1280×880 的定尺画布，真页面是响应式的，逐像素比对没有意义——比出来的差异全是断点造成的，跟设计对不对没关系。

要看的是气质有没有走样，三件事：

- **留白的比例** —— 正文占屏幕的几分之几，跟样张还差不多吗
- **字的轻重** —— 标题的字重、大小关系，有没有在落地过程中被"稳妥"地改重改小
- **主色出现的次数和位置** —— 样张里一屏一次的东西，落地页是不是变成了满屏都是

这一问只有人能答。下面那些机器能查的，回答不了它。

---

## 二、六项体检：全是踩过的

`scripts/verify-page.mjs` 查这六项。每一项都不是想出来的，是真在某一次落地里翻过车的：

| | 查什么 | 为什么在这个名单上 |
|---|---|---|
| 必修 | 整页横向滚动 | 桌面上看不出来，手机上一滑就露 |
| 必修 | 控制台报错 | 「代码看着没问题」和「浏览器里没报错」是两件事 |
| 必修 | **图片被拉变形** | CSS 只写了 `width`，HTML 的 `height` 属性还在生效。默认 `object-fit:fill` 会按盒子把图抻变形——所以查的是 fill，不是跳过它。cover/contain 是有意裁切，不查形变 |
| 该修 | 图片规格远超显示尺寸 | 一张 1.1MB 的 PNG 塞进 272px 的槽。页面照样「能看」，所以永远没人管 |
| 该修 | 正文对比度低于 WCAG AA | 设计稿上「淡一点更高级」，落到正文就是看不清 |
| 该修 | 关掉 JS 还剩多少正文 | 落地页是给陌生人第一眼看的。整页靠客户端渲染 = 首屏白屏 + 抓不到 |

```bash
node scripts/verify-page.mjs --url http://localhost:8000 --proof 样张截图.png --out verify/
```

产出 `verify/REPORT.md`、三档视口的整页截图，以及 `side-by-side.png`——样张和落地页并排，就是为了第一问。

有必修项时退出码为 1。

---

## 三、它查不到什么（这一段比上一段重要）

**工具不猜。量不准的地方它会明说「没量到」，不会编一个数字。** 具体有三类：

- **文字用了 `background-clip:text`** —— 也就是渐变标题。**这恰好是最容易出对比度问题的地方，也恰好是这个工具的盲区。**
  一套用金渐变做大标题的设计，工具会一声不吭地跳过它，报告显示"0 项该修"——但那个标题可能连 AA 大字的 3:1 都不到。**渐变标题的对比度必须手算，别指望这个脚本。**
- **底是渐变、图片或半透明叠色** —— 合成之后的实际底色算不准，与其给个错数不如不给
- **文字本身半透明** —— 同上

还有一整类它根本不碰：**动效**。入场、hover、滚动触发、过渡曲线——静态截图零信号。这一类只能自己开着页面滑一遍。

控制台报错这一项会**忽略 Google Fonts / fonts.gstatic 加载失败**。受限网络里这是噪音，不是页面的错；别的 `console.error` 和 JS 异常仍算必修。

---

## 四、装不上就退回肉眼

和收料那一步一样，**保底路径必须存在**：

1. `scripts/verify-page.mjs`（要 playwright）
2. playwright 版本和机器上的 Chromium 对不上 → `--exe /path/to/chrome` 指一个现成的
3. 都不行 → **自己截图，跟样张并排贴回对话里**

第 3 条任何环境都走得通，而且它覆盖的正是唯一必须回答的那一问。前两条只是把附赠的六项体检自动化了而已——**别把手段当成目的。**
