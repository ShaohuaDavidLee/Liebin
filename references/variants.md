# 三变体：怎么分、怎么渲染、怎么问

## 一、轴的选择

三个变体必须沿**一条**轴排开，而且这条轴要能用一句话说清。三个随机好看的方案，用户选完你什么也没学到。

轴由"缺哪类信息"决定（详见 `intake.md`）：

- 只有图 → **数值松紧**：紧凑 / 基准 / 舒展
- 有 DOM → **取舍程度**：忠实复刻 / 取其气质 / 反向克制
- 有 design md → **信息密度**：高 / 中 / 低
- 只有一句话 → **气质解读**：三种不同的理解方向

给每个变体一个**两个字的名字**（如「照搬」「取气」「反手」），比 A/B/C 好记，用户反馈时会自然引用这个名字。

## 二、第三个变体要故意偏离

尤其是参考来自单张图片时。用户贴那张图，往往不是真的想要那张图，而是没有别的语言描述自己想要什么。第三个变体的作用是提供对照，让"我不要什么"变得可说。

偏离的方向不要随机——**沿着"如果把参考里最显眼的那个特征拿掉，还剩什么"来做**。参考是全屏大图？第三个变体就不用图。参考是超大衬线标题？第三个就用中等无衬线。这样用户的反应能直接告诉你：那个特征到底是不是他要的。

## 三、必须渲染三屏

| 屏 | 为什么 |
|---|---|
| **首屏** | 气质在这里定 |
| **核心操作屏** | 表单、列表、输入——设计语言在功能压力下会不会垮 |
| **空状态 / 结果屏** | 最能暴露风格撑不撑得住，也是所有 AI 样张都会跳过的地方 |

只做首屏的样张是假的。绝大多数"看着挺好后来崩了"的案例，崩在第二三屏。

## 四、渲染规则

**用真实文案。** 不许 Lorem ipsum、不许"标题标题标题"。中文文案的长度、语气、断行会彻底改变一个设计成不成立——一个为 "Where dreams rise" 设计的版式，换成"记录你这一周的身体变化"就是另一回事了。用户没有文案就先帮他写，让他改完再渲染。

**数值全部转 em。** 从参考迁移过来的字距、行高、内边距、圆角，先除以对应字号。绝对 px 只在一处保留：容器最大宽度。

**中文的四条硬规则**（拉丁文 spec 直接搬会翻车）：
1. 标题不用负字距（`letter-spacing: 0` 起步，要收紧最多 `-0.01em`）
2. 正文行高 1.7–1.9，不是拉丁文的 1.4–1.6
3. 中文没有真正的 300/500 字重——多数中文字体只有 4-5 档，字重映射要重做，别指望 `font-weight: 500` 有效果
4. 中西文混排之间留 0.25em

**技术约束**：单文件 HTML，内联 CSS 和 JS，除 Google Fonts 外无外部依赖，双击能直接打开。别用框架、别用构建工具——这张样张的寿命是二十分钟。

**并列而非分页。** 三个变体必须能同屏对比。做法：每个变体一列，用 `transform: scale()` 缩到能并排（推荐三列各占 1/3 宽，内部按 1280px 设计再缩放），底部横向滚动切换三屏。用户要能左右扫视，不能来回点。

模板见 `../assets/preview-template.html`。

## 五、样张底部必须带确认区

样张不只是给人看的，还是收集判断的工具。底部放一个表单，三个问题（见 SKILL.md 第三步），带一个「复制我的选择」按钮，把用户填的内容拼成一段结构化文本复制到剪贴板，用户贴回对话里给你。

不要用 localStorage（在部分环境不可用），用一个 JS 变量存就行——这张页面的生命周期就是一次填写。

## 六、拿到反馈之后

**用户的原话不要润色。** "这个圆角太软了""字太挤了""这个蓝色太商务了"——这些话直接逐字进 DESIGN.md 的 Don'ts。改写成"保持适度的圆角""注意字间距"就废了，对后续生成零约束力。

**三个都不要的时候**，先定位错在哪一层再动手：

| 用户的反应 | 错在 | 怎么修 |
|---|---|---|
| "都不是这个感觉" | 气质层 | 换参考，别调参数 |
| "感觉对了但看着不舒服" | 数值层 | 保持方向，重新拉轴 |
| "好看，但不像我的产品" | 匹配层 | 回到"用户在什么状态下打开"那一问，重新想 |

这三种错用完全不同的方法修。不先定位就调参数，是最常见的时间黑洞。
