# 收料：四条入口，各自能拿到什么、必然缺什么

核心认知：**不同来源提取到的不是同一份东西的不同精度，而是不同类别的信息。**
图片给构图和气质，DOM 给数值，人写的 spec 给意图。缺哪一类，决定三变体沿哪条轴分。

---

## A. 只有一张图 / 截图

**做法**：直接看。多模态模型读图不需要任何工具、API、浏览器——这是四条路里最顺的一条，零依赖。

**能拿到（可靠）**
- 版式骨架：几栏、导航形态、内容块的相对位置和占比
- 字体分类与对比关系：衬线/无衬线、高对比/低对比、标题与正文的反差有多大
- 色彩关系：主色、文字色、按钮色的**关系**（谁压谁、对比度大概几比几）
- 构图节奏：留白比例、文字块占屏幕的几分之几、视觉重心在哪
- **气质判断**：宁静/张扬/紧凑/奢侈/廉价——这一类 DOM 永远拿不到，是图片独有的优势

**拿不到（不要编）**
- 任何绝对像素值。截图宽度不等于视口宽度（可能是 2x 屏），80px 和 40px 在图里没法区分
- 字距、行高的精确值。可以判断"很紧""偏松"，不能报数
- 字体的具体名字。只能给候选，标明是猜的
- **全部动效**：入场动画、stagger 延迟、hover 状态、transition 曲线——静止图零信号
- 移动端断点和响应式行为
- **静态图 vs 视频背景分不出来**。一张风景背景，可能是 `<img>` 也可能是 `<video>` 循环播放——这个区别对最终观感影响巨大，但截图里完全不可见。**遇到大面积背景图，一定要问一句"这是图还是视频"**

**因此**：这条路的三变体沿"数值解释的松紧"分（紧凑 / 基准 / 舒展），让用户用眼睛替你定那些拿不到的数。

---

## B. 有网址

**降级阶梯**（一定要按顺序退，永远保证有一条不装任何东西也能走通的路）：

1. **Chrome DevTools MCP / Playwright**：取三档视口截图 + DOM + computed CSS。最全
2. **WebFetch**：拿到 HTML 和内联样式。动态站点会失手，静态站点够用
3. **让用户自己截图**：退回 A 路。**这一级是保底，任何环境都能走**
4. **让用户贴一段他觉得关键的 CSS**：用户会贴他在意的部分，反而是有效的信噪过滤

**能拿到**：精确 computed 值、字体真名、CSS 变量、keyframes 和 hover 规则、断点、video 的 src

**拿不到**：**判断**。DOM 会把页面上所有 token 一股脑倒出来——三十种灰、十二个字号、四套阴影——但不会告诉你哪三个是这套设计的骨头、哪二十七个是历史遗留。全量提取的结果是资产清单，不是设计语言。

**因此**：这条路的三变体沿"取舍程度"分（忠实复刻 / 取其气质 / 反向克制）。你要用变体逼用户回答"这套东西里你到底要哪部分"。

> 别在这一步跟提取器比准。提取器已经免费且成熟，你的价值在下一步。

---

## C. 有一份现成的 design md

**最好的输入**，因为它通常已经包含了意图散文（"to achieve the high-fashion editorial look"）。

但要**先审一遍**再用，重点检查三处：

- **绝对像素**：把所有 px 除以对应字号转成 em。`letter-spacing: -2.46px` 在 `font-size: 80px` 下是 `-0.031em`，这才是可迁移的形态
- **语言假设**：整份 spec 大概率是给拉丁文写的。中文要重算——中文没有真正的 300/500 字重、行高要更松（1.7–1.9 而非 1.4）、不用负字距、中西混排要留 0.25em 间隙。见 `design-md.md` 的 CJK 段
- **有没有"什么时候别用"**：99% 的 design md 只说怎么做，不说什么场景不适合。这一栏永远是空的，正好是你要补的

**因此**：这条路的三变体沿"落到你的内容上的信息密度"分（高 / 中 / 低），因为设计语言已定，未知量是它和用户真实内容的合身度。

---

## D. 什么都没有，只有一句话

比如"我想要那种很高级的感觉""像小红书那种"。

**不要追问细节**——用户说得出来就不会这么说了。直接出三个不同气质的解读，让他用排除法。这条路反而是三变体价值最高的，因为它把一次开放式的描述题变成了一次三选一的选择题。

可以先去 designmd.app（561 个现成 DESIGN.md）挑三个气质差异明显的做起点，省掉从零构造的时间。

---

## 目标：你现在长什么样（跟「参考」是两回事）

上面 A–D 讲的都是**参考**——我想要那样。还有一条独立的线：**目标**——我现在是这样。

这两条经常同时存在，而且**目标那一条最容易被跳过**，因为用户贴参考贴得很积极，却默认「我自己的东西你反正看得见」。看不见。

| 目标的形态 | 能白拿到什么 |
|---|---|
| 线上网址 | 真实文案、真实信息密度、现有配色与字体、现状基线 |
| 本地代码路径 | 同上，外加现有的 token 和组件结构 |
| 现有稿的截图 | 真实文案（要自己抄下来）、密度、气质 |
| 什么都没有（全新产品） | 什么也没有——**必须先跟用户把三屏文案写出来** |

**为什么值得专门问一句**：真实文案是这套流程唯一不能省的输入，而一个现成的地址直接把它解决了。
用户手上有网址却没给，你就会退回去让他现打一遍文案——他多半会敷衍，你就拿到一份半真半假的文案，
样张也就跟着半真半假。

**两个坑**：

- **别把参考网址当成目标网址。** 「照着 A 做我的 B」里 A 是参考、B 是目标。搞反了，三个变体会全在复刻用户已经不满意的那一版。
- **现状不是第四个变体。** 可以并排展示，但要标清楚它是基线。混进选项里，用户会因为「熟悉」而选它，那不是判断，是惯性。

---

## 收料清单（进下一步之前对一遍）

- [ ] 参考的来源类型确定了，知道自己缺哪一类信息
- [ ] **问过「你现在有没有一版」** —— 有网址 / 本地代码 / 现有稿截图，就直接拿过来
- [ ] 参考和目标没有搞混（哪个是「我想要那样」，哪个是「我现在是这样」）
- [ ] 拿到了**真实文案**（三屏各自的标题、正文、按钮字），不是占位符
- [ ] 知道这个产品给谁用
- [ ] 如果参考里有大面积背景媒体，问清了是图还是视频
- [ ] 所有绝对 px 已转成 em / 比例
